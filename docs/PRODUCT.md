# Stepwise product completion criteria

The product is a personal software-engineering learning environment, with a coherent beginner-to-project progression. Completing a course is not a claim of professional expertise.

## Required

- Authored Python, JavaScript, SQL, algorithms, API/security, and systems/AI foundation curricula, with prerequisites and reliable resources.
- Executable assessment suites, including edge cases, distinct from examples. Completing a coding lesson requires tests and its knowledge check. Reading or typing a long reflection does not prove mastery.
- Substantial projects with requirements, test suites, a self-review rubric, and exportable work.
- Useful error output, progressive hints, deliberate debugging practice, and reference solutions disclosed as learning aids.
- Durable personal progress with migration, backup validation, restoration, and clear local/cloud status.
- Retrieval practice and spaced reviews with accurate due dates, plus progress and study activity derived from real events.
- Responsive, keyboard-accessible navigation, browser history, readable code, and accessible status updates.
- All solutions tested; incorrect solutions rejected; browser workflows tested against the production build.
- Vercel deployment configuration and verification of the actual public deployment when hosting authorization/network access is available.

## Account scope

The user was asked whether cross-device sync and other learners are needed. Local use must remain functional without credentials. If cloud sync is required, it needs an actual authenticated backend, access control, migrations, and a configured project; a sign-in mock is not sufficient.

## Release truthfulness

Do not call an unverified public deployment live. Do not describe quizzes as proof of expertise. Do not label unauthored advanced courses available. Show limitations in the relevant learning tools.
